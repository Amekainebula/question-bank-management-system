# 题库管理系统需求追踪矩阵

本文将任务书要求、软件需求、系统实现和测试证据关联起来，避免只完成页面而遗漏验收目标。

| 任务书/需求 | 实现位置 | 验收入口 | 测试证据 |
| --- | --- | --- | --- |
| 课程管理 | `app.js` 的 `renderCourses`、`saveCourse` | 教师或管理员 → 课程管理 | TC-05、TC-08 |
| 题型管理 | `renderTypes`、`saveType` | 教师或管理员 → 题型管理 | TC-17 |
| 试题管理 | `renderQuestions`、`saveQuestion` | 教师或管理员 → 试题管理 | TC-06、TC-07、TC-08 |
| 试卷生成管理 | `renderPapers`、`savePaper`、`paperFormTemplate` | 教师或管理员 → 试卷管理 | TC-09、TC-10、TC-11、TC-12 |
| 至少3个 Actor | `roleMeta`、`navItems`、登录演示账号 | admin / teacher / student | TC-02、TC-03、TC-04 |
| 10个以上实际功能 | 需求规格说明书 F01-F12 | 各角色综合演示 | TC-01 至 TC-20 |
| 在线答题 | `examTemplate`、`examQuestion` | 学生 → 在线练习 | TC-13、TC-14 |
| 自动判分 | `isAnswerCorrect`、`submitExam` | 学生提交试卷 | TC-15 |
| 成绩分析 | `renderResults`、`renderAttemptTable` | 学生/教师/管理员 → 成绩分析 | TC-14、TC-16 |
| 错题复习 | `getStudentMistakes`、`renderMistakes` | 学生 → 错题本 | TC-16 |

## 任务书要求与实现边界

- “课程管理、题型管理、试题管理、试卷生成管理”是任务书明确要求，本项目全部实现。
- “至少 3 个 Actor、10 个功能”是任务书明确验收条件，本项目使用管理员、教师、学生 3 个 Actor，并按 F01-F12 核算 12 个功能。
- CRUD 不重复计数：用户、课程、题型和试题的增删改查分别各算一个管理功能。
- 系统实现采用本地浏览器数据持久化，满足课程设计可演示要求；生产部署所需的后端数据库和统一认证属于后续扩展，不在本次课程设计范围内。
