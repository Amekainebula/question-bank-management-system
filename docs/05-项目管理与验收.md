# 题库管理系统项目管理与验收

## 1 阶段计划

任务书要求课程设计依次完成选题、需求分析、软件设计、系统实现、系统测试和验收。本项目按以下产出组织工作：

| 阶段 | 主要活动 | 产出 | 验收重点 |
| --- | --- | --- | --- |
| 选题 | 明确题库系统范围和目标 | 需求陈述 | 题目范围清晰 |
| 需求分析 | 识别 Actor、用例和边界 | 软件需求规格说明书 | 至少3个 Actor、10个功能 |
| 软件设计 | 确定架构、数据模型、页面和流程 | 设计文档 | 设计可支撑实现 |
| 系统实现 | 完成界面、业务逻辑和数据持久化 | 可运行系统 | 主要流程可演示 |
| 系统测试 | 执行功能、回归和兼容性测试 | 测试报告 | 测试证据完整 |
| 验收 | 按需求追踪矩阵逐项演示 | 项目全部材料 | 任务书要求全部覆盖 |

## 2 小组分工模板

任务书规定每组 4 人。提交前请将下表的“待填写”替换为实际姓名和学号。

| 角色 | 成员 | 工作内容 |
| --- | --- | --- |
| 组长 | 待填写 | 计划协调、需求确认、最终汇报 |
| 需求与设计 | 待填写 | 需求陈述、需求规格、用例和数据模型 |
| 系统实现 | 待填写 | 页面、表单、组卷、答题和权限功能 |
| 测试与文档 | 待填写 | 测试用例、缺陷记录、材料整理和验收演示 |

## 3 风险与应对

| 风险 | 影响 | 应对方案 |
| --- | --- | --- |
| 需求理解不一致 | 返工、文档与代码不一致 | 以需求追踪矩阵为单一检查清单 |
| 题型规则复杂 | 表单和判分出错 | 先覆盖五种常用题型，并对每种题型单独测试 |
| 组卷遗漏或总分错误 | 试卷不可用 | 选择题目时实时计算题数与总分 |
| 角色权限混乱 | 学生看到管理功能 | 登录后按角色生成菜单，并做三角色回归测试 |
| 演示环境缺依赖 | 无法启动 | 使用 Node.js 内置服务器，不依赖第三方包 |

## 4 验收脚本

### 场景 A 教师建题并组卷

1. 使用 `teacher / 123456` 登录。
2. 进入“试题管理”，点击“新建试题”，切换题型并填写答案解析。
3. 进入“试卷管理”，点击“创建试卷”，勾选试题，核对题数和总分。
4. 保存草稿，打开试卷详情并点击“发布试卷”。

### 场景 B 学生练习并复盘

1. 退出教师账号，使用 `student / 123456` 登录。
2. 进入“在线练习”，打开已发布试卷。
3. 完成选择题和填空题，点击“提交试卷”。
4. 在“成绩分析”查看得分，在“错题本”查看答案解析。

### 场景 C 管理员维护基础数据

1. 使用 `admin / 123456` 登录。
2. 进入“用户管理”查看三类用户。
3. 进入“课程管理”和“题型管理”查看 CRUD 操作。
4. 尝试删除被试题引用的题型，确认系统阻止删除并提示原因。
